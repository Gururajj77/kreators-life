# Where each change is told

Made 2026-11-07 for the founder's ask: "the changes in help docs, the course/cohort and frontend website for all changes/updates we made so far according to context and alignment of whether they should be there or not and where they should be". Three agents carry this out, one per place, and decide nothing: the words here are the words to use, and where a cell gives facts instead of words, the lesson's voice decides the sentence and the facts stay as given.

Read against docs/DECISIONS.md up to the 2026-11-07 red yes line, the reports in the session's reports folder, the code at about 12:20 IST, every lesson, `help.ts`, `terms.ts`, `HELP_FAQ`, `Help.tsx`, `content.ts`, the site pages and the policy pages. Line numbers are from then, so match on the quoted words. Rows 70 to 86 came later the same day, from the last content pass, for what landed after this file was written.

**The depth rule.** Help says how it works. The course teaches why and how to use it. The site says only what the app does for a visitor deciding whether to join: no result, number, certification, health or therapy outcome, and nothing oversold. The team's tools live in the Admin guide, never on the site.

**Codes.** `O07` is `scripts/onboarding-guide/lessons/07-*.md`, `A07` is `scripts/admin-guide/lessons/07-*.md`. `HT.today.3` is `HOW_TO.today`, step 3, in `packages/shared/src/help.ts`. `T.map` is the `map` key of `TERMS` in `packages/shared/src/terms.ts`. `FAQ` is `HELP_FAQ` in `packages/shared/src/wellbeing.ts`, shown on Help. `F.journal` is `FEATURES.journal` in `apps/web/src/site/content.ts`. `H1`, `C1`, `W1` point at the numbered lists of wrong text below. `S1` is the one sentence defined at the top of the onboarding list. "Done" means the text is already there and was checked; it needs no work.

**For the Help agent.** `HOW_TO` keeps three to five steps per app (a shared test) and every key in `terms` must exist in `TERMS`, and every `TERMS` key must sit in one `TERM_GROUPS` group. `TERMS` and `HELP_FAQ` are in the shared chunk: everything below adds about 1 kB, so add nothing beyond it and run the budget. `HOW_TO` is its own chunk. `earningGuide` takes nothing: no change since the course was written pays anything new (a shared test also keeps supplements out of it). Score with `python3 -I scripts/flesch.py --strings <file>`.

**For the course agent.** Lessons need "In this lesson you'll learn", "**Pro tip", "**Result:**" and "## The bottom line", carry no links, and must score 60 or above with `node scripts/onboarding-guide/build.mjs --check` and `node scripts/admin-guide/build.mjs --check`. Say "a few", never a number or a time, about the setup chat's questions. The founder's book courses take nothing. Two new onboarding lessons go in by number with `AFTER = { 18: 5, 19: 7, 20: 11 }`; one new Admin guide lesson with `AFTER = { 24: 3, 25: 7 }`. Files alone change nothing on screen: bring the databases up with one new migration at the next free number (`build.mjs --sync <file> --order` for onboarding, `build.mjs --sync <file>` for the Admin guide, as 0097 was made), apply it through the restart script, and change CLAUDE.md's "17 lessons" to 20. Do not regenerate 0088 or 0096.

**For the website agent.** Keep each `more` line one short fact, and read amounts from `LIVE_CALL_CENTS`, `PLAN_CURRENCY` and `money()`, never typed. `LEGAL_VERSION` stays as it is: bumping it is the founder's call (see the end). Run the density and rag probes over `/features/*` and `/`, since a new `more` line lands on a phone inside a Fold.
