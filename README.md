# kreators.app

Seven relationships, one tower, a few boxes to tick every day. Around that daily game sits everything a creator needs: learning, paid work, brand campaigns, content rewards paid per verified view, events, a shop with attribution, a money tracker, and a public site that shows all of it before anyone signs in.

## Stack

- `apps/web`: React 19 + Vite 7 + Tailwind 4, installable PWA. The public site and the app are one bundle.
- `apps/api`: Cloudflare Worker (Hono) with a D1 database. It serves the built web app as static assets, so one deploy ships everything. `/api/*`, `/go/*`, `/sitemap.xml`, `/__scheduled` and the site home `/` run in the Worker (the home only to make the share-image URL absolute for link previews); everything else is a file or the SPA shell. The PNG icons and the share card in `apps/web/public` are rendered from `scripts/icons/*.html` by `scripts/icons.sh`; `icon.svg` stays the favicon and the source of the shape.
- `packages/shared`: the domain model both sides use: relationships, the ladder, XP rules, questions, modules, listings, commerce, finance.

## Run it locally

```bash
pnpm install
pnpm db:migrate:local      # creates or upgrades the local D1 database (migrations 0001 to 0027)
pnpm --filter @kreators/shared test   # unit tests for money, time, slots, matching and flags
pnpm dev                   # web on http://localhost:5173, api on http://localhost:8787
```

- http://localhost:5173 is the live dev server with hot reload. It proxies `/api` and `/go` to the Worker.
- http://localhost:8787 is the Worker serving the last `pnpm build`. Use it to check the production bundle and the PWA.
- `bash scripts/smoke/blueprint.sh` runs the end-to-end smoke test and `node scripts/smoke/shoot.mjs` takes screenshots, both against a second API on port 8788 with its own database under `scripts/smoke/state`, so the dev database behind 8787 holds only real local accounts. `bash scripts/scan.sh` runs the spacing and colour scans and `scripts/flesch.py` scores reading ease.
- `pnpm dev` starts the api with `--test-scheduled`, so the cron can be run by hand: open `http://localhost:8787/__scheduled?cron=*+*+*+*+*`. The job posts post-purchase sequences and monthly finance entries, sets circle tables two days out, and refreshes YouTube numbers.

Sign-in is email and password, built in (no auth package): sign-up asks for the password twice and checks it against one shared rule (eight to 128 characters, not a common password, not one character repeated, not your email), and asks for a phone number and a date of birth (you need to be eighteen or older; the phone can be changed later, the date of birth cannot, and neither is shown to anyone), passwords are PBKDF2 with a 16-byte random salt, sign-in answers the same for an unknown email and a wrong password and takes the same time, one account can only be tried twenty times per quarter hour from anywhere on top of the per-address limit (every limit in the app, from sign-in to posts, chats and applications, is one line in `apps/api/src/limits.ts`), changing a password needs the current one and signs out every other device, and every API answer carries the standard security headers. A device with progress on it keeps that progress when an email is added. Forgot your password: a one-time reset link (hashed at rest, thirty minutes, same answer for any email) goes out through the mail outbox and signs every device out when used; without Resend credentials the mail waits in the outbox under Admin, Ops, where an admin can pass the link on. The founders' addresses in `apps/api/src/admins.ts` (plus any in `ADMIN_EMAILS`) become admins the moment they sign up or sign in, so sign up with them right after a deploy. The public site's "Go to app" goes to sign-in (or straight to Home with a session) and "Start free" goes to sign-up. The admin console is tables all the way down: sort, search, filter, tick rows to change several at once, edit role, Pro, flags, rollout, live and featured in the row, and page through 10, 25, 50 or 100 rows at a time, as every long list in the app does. On a phone the top-right corner holds the theme button and an apps menu that lists the same groups the laptop sidebar folds (the bottom tabs stay); a phone turned sideways keeps the phone layout. Sign out lives in the laptop sidebar, in that phone menu and at the top of the Profile tab; an account that has no email yet is warned first, since nothing can get back to its progress. A new account starts empty: nothing is seeded on sign-up, and there is no demo or mock data anywhere in the app. `apps/api/.dev.vars.example` lists every local key. Secrets go in `apps/api/.dev.vars` locally and `wrangler secret put` in production:

| Name | What it does |
| --- | --- |
| `ADMIN_KEY` | Opens `/admin` before the first admin account exists. |
| `YOUTUBE_API_KEY` | Reads view counts for YouTube links in Content and content rewards. Without it, numbers are typed and a reviewer confirms. |
| `META_APP_SECRET`, `META_VERIFY_TOKEN`, `META_ACCESS_TOKEN` | Turn on the Instagram comment webhook and private replies for Auto-DM. Without them, matched comments queue for you to send by hand. |
| `CLICK_SALT` | Salt for hashing click IPs on tracked links. |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` | Money checkout goes live: orders are created at Razorpay, the browser opens Razorpay Checkout, and `/api/webhooks/razorpay` marks the order paid after the signature checks out. Without them money orders are recorded in test mode. |
| `RESEND_API_KEY`, `EMAIL_FROM` | Transactional email (receipts, confirmations, KYC decisions, invoices). Every message is kept in the outbox under Admin, Ops, whether or not it was sent. The key needs Resend's "Sending access"; the From must be on a domain verified in Resend. |

## Deploy

Everything runs from the repo root.

```bash
pnpm cf:login              # opens the browser once; pnpm cf:whoami shows the account, pnpm cf:logout switches it
pnpm db:create             # makes the D1 database; paste the printed database_id into apps/api/wrangler.jsonc
pnpm db:migrate            # applies every migration to the live database
pnpm cf:secret CLICK_SALT  # asks for the value; repeat for RESEND_API_KEY, EMAIL_FROM and any other key you use
pnpm deploy                # builds the web app and ships it with the Worker
pnpm cf:logs               # live request and cron logs from the deployed Worker
```

The `cf:` prefix is there because `pnpm login`, `pnpm whoami` and `pnpm logout` are pnpm's own npm-registry commands and would never reach wrangler.

After the first deploy, sign up with the founder addresses before sharing the link.

## Design source

Colors, type, radii and shadows come from the freud UI Kit v1.5 in Figma. The values are frozen in `design/figma-tokens.json`, so builds never call Figma. To re-pull, put a read-only Figma token in `.env` as `FIGMA_TOKEN` and run `python3 -I scripts/figma-pull.py . <fileKey> <nodeId> <outDir>` followed by `scripts/figma-sections.py`, then update the theme block in `apps/web/src/app.css` and the floor colors in `packages/shared/src/index.ts`.

Dark mode keeps the same hues and turns them inside out: the cream page becomes deep brown, cards become brown, pale tints become the deep end of their own family (pale purple turns deep purple, not grey). Everything is a CSS variable on `:root`; the theme switch (device, light, dark) sits on every page, including onboarding, and in the laptop sidebar.

On a phone the app is a single column with tabs along the bottom. On a laptop the tabs become a sidebar and each screen's sections flow into two columns. The public site is fully responsive on its own.

Every screen is built from the same few parts so nothing reads as haphazard: `PageHeader` (the way back as a round button, the title, one line on what the screen is), `Section` (same heading size and gap everywhere, with an optional "Open" link on the right), `StatTile` for a number with its name and a hint, and the charts in `components/Charts.tsx` (`Bars`, `HBars`, `Sparkline`, `Ring`). Resting cards carry a hairline edge plus a soft drop, defined once as `--shadow-toy-soft`, so they read on cream paper and in dark mode. On any solid colour the foreground is white, as the kit draws it (yellow is the one fill that takes brown); dark text and ink buttons sit only on cream, card and tint surfaces. The chart set in `components/Charts.tsx` mirrors the kit: smooth area lines with a soft fill (one series or several), tall pill bars, gauges, donuts with a legend, packed bubbles, a month grid, a mood-face row, and the small marks on tracker rows. Moods are drawn faces (`components/MoodFace.tsx`), the kit's coloured discs with a simple face, not system emoji. Every hero (`components/Hero.tsx`) carries one of the seven characters, whose mood follows the number beside it; the metric cards on Home carry them too. Every line chart sits in a visible frame: a y axis with three labels, a baseline, dashed gridlines and x labels, drawn even when nothing is logged yet so the chart reads as a chart. Home has a full-width "This week" chart with mood, sleep and calm as scores out of a hundred, xp per day over fourteen days, and orders per day when the shop is on; Life repeats the week chart; each metric screen has a thirty-day line; Finance has six-month lines for in against out with money on the axis; the Shop overview has orders per day. Anything tappable is a `toy`: it lifts under a pointer and presses on tap. Primary actions are solid ink pills; secondary ones are outlined.

## Home dashboard

`/home` is where the app lands after sign-in. It follows one rule, results first, then what did it, then the one thing to do next: four tiles (xp today, streak, points, level), the day's three boxes with a line that names the next box and what it will not work without (`nudgeFor` in shared, unit-tested), xp per day for fourteen days with a dot on days a task was ticked, the five life areas as rings, the seven floors as bars, money in and out with dues when Finance has entries, orders per day when the shop has products, what is next (events, sessions, circles with when the chat opens), and a grid of shortcuts into every app that is switched on. One call, `GET /api/home`, feeds it. The layout follows the kit's Home frame section by section: a dark header with the date, your character, "Hi, name!" and three small pills (level, streak, today's mood) over a search field; a scrolling row of coloured metric cards (life score, mood with the week's bars, wellbeing); four solid stat tiles in the kit's stats style (streak, xp today, points, level); the day's three boxes as a green card with a big count, chips for each box and the guidance line; a tracker list where each row carries a small visual (sparkline for mindful minutes, a ring for sleep, a fourteen-day grid for journal days, segments for stress, the last three moods with arrows); an "Up next" card with a big count and rows for events, sessions and circles; the companion as a dark card with the message count and two round buttons; two cards from Knowledge; then the game's own views. Life uses the kit's score hero with a bar per area, and Wellbeing carries the kit's mood-history row.

## Accounts and roles

Everyone starts with an anonymous device session. Under You, Account, a person can add an email and password; the tower on the device becomes that account. Signing in from a public page brings you straight back to it.

Three roles: Creator (`user`), Staff (`sub_admin`) and Admin. Staff hold permissions, each a job they are trusted with: talent (campaigns), cohorts (School), events (Party), finance (payouts), moderation, support, review (Club, rewards, tools, TV and Fund) and mentor (assignment feedback). Admins hold them all. Brands are organizations: whoever creates one owns it and adds teammates by email.

## Modules and feature switches

Every part of the app is a module in `MODULES` (`packages/shared`). People switch modules on and off under You, Features. Admins control each module with a global switch, a minimum role, a rollout percentage and overrides for one person, one role or one brand, with an optional expiry. The server resolves all of that into `access` on `/api/me`, so the client never guesses, and refuses the API of a module that is not available to the person, so a switched-off app is off for real and not only hidden.

Learn and earn: School (programs, cohorts, lessons, assignments, mentor feedback, sessions, completion), Work (opportunities, one application each with the portfolio attached, status tracking), Army (brand campaigns: brief, scope, shortlist, approval, production, versions and feedback, usage rights), Win (content rewards).

People: Party (meetups anyone can host, staff events, RSVP, waitlist with promotion, check-in, feedback), Kreators Run (run clubs with a start code per run, kilometre tracking, run badges, brand collabs with giveaways), Community, Club (curated membership with a reviewer queue, club-only Work listings that only members see, and a named manager on staff), Bond (introductions that only share details after consent, with blocking), Circles (anonymous nearby tables matched by interests).

Wellbeing: Life dashboard, score, Mood, Sleep, Stress, Mindful minutes, Journal, Companion. Journal and wellbeing data never reach brands, staff, the leaderboard or Club selection.

Creator: Profile (handle, bio, skills, portfolio), Shop, Audience, Content, Auto-DM, Finance, My purchases, Knowledge, Tools, TV, Fund.

School ships two real programs seeded from the skill files in apps/web/public/resources: Editing fundamentals (seven lessons on the cut, framing and finishing) and Skills using ChatCut and AI (seven lessons on skills, gates, hooks and verification), each with a self-paced open cohort, one assignment, and a link from every lesson to the full skill file. The public page shows earned badges and awarded honors behind their own switch, and carries a links page like a Linktree: link buttons (plain or featured), headers, text, images, YouTube videos and carousels, stacked in any order, each tap counted for the owner, with a "Made with kreators.app" footer that leads back to the site. On a laptop the sidebar's app groups start folded. Core: Today, Tower, Search, Inbox, Help (FAQ and support tickets), Rank, Rewards. Team: Manage (queues per permission), Admin. Internal (staff and admins only): Observability at /internal/observability, which counts people, lists every account with the apps it has on, counts people per app, lets an admin change roles (audited, never their own) and embeds the build map. Each role has a badge on the profile picture and under the logo in the sidebar.

## Words, and the pyramid

The app speaks at a teenager's reading level (Flesch 60 or above; a scorer lives in the scratchpad). The tabs are Home, Daily, Pillars, Apps and Profile; the app groups are Contribution, Creation, Connection, Reflection, Essentials and Operations, plus Internal for the team. Every screen is one full-width column on a laptop; only Home uses two. Interests are grouped the way a dating app groups them, for everyone, with ten on at most. Search is inline: results appear under the field as you type. The seven relationships are *pillars*; each pillar is a *pyramid* with six layers from the base up: a foundation (one thing you will not let break), a guiding principle (a line you live by so it holds), a value goal (how you want to feel more often), a goal outcome (what you would see when that is real), a project, and tasks. The five *areas of life* under Life keep that word. The daily nudge from your weakest pillar is a *small act*. Under the tasks, Daily keeps a *not to do* list: things you are staying away from, up to seven, each with its own streak of kept days; a tick means you kept it today, a slip or a missed day starts the run over, and a kept day pays a little xp once. Reviews, under Reflection, is the place to look back: pick a week, a month, a quarter or half a year and see the numbers from every app for that period next to the period before (check-ins, tasks, small acts, xp by pillar, kept days, mood, sleep, stress, mindful minutes, journal entries, money in and out, orders and sales, lessons, applications, events, posts and circles), then answer a few questions, rate how it went with a face, and keep one line to remember. Every review is saved with the numbers as they were. Each cadence has a built-in set of questions, and you can add recurring templates of your own. The same period filter sits on Home, Life, Finance, Wellbeing, the trackers, Journal and the Shop as a "By period" panel. The Store, under Creation and off by default, has three shelves: new gear and software that only the team stocks, bought through partner links (the tap goes through `/out`, counted with a salted hash, and Kreators may earn a share); pre-owned gear from other creators, graded by condition, with offers the seller accepts or declines and a chat per buyer, the handover and money settled between the two; and kits by stage and budget that mix both. A featured spot is a week at the top: free from the team, 200 points for a seller's own listing, with a yellow tag on the card, and the same spot exists for tools. Bundles of a creator's own products stay in the Shop. Community is a feed you can sort by recent, popular or most replies and filter to everyone, people you follow or your own posts, with a follow button on every post; a post, a reply, a like, a like received and a new follower each pay a little xp or a point, capped by the day and paid once. Every seller carries a trust score out of a hundred built only from what they earned here (xp, points, best streak, time here, sales and rating, honors), shown on their public page, their product pages and their pre-owned listings. Some things can be gated: a product, a store item or a tool can ask for a points balance, a badge, or both, and says so in plain words until you have earned it. Kreators Run, under Connection and off by default, is Party for runners: anyone starts a run club (city, pace, where it meets), members join, the host adds runs and gets a six-letter start code for each one that only the host ever sees. A member logs a run by entering that code from thirty minutes before the start until three hours after the end, once per run; the entry pays 20 xp and 10 points (two paid runs a day at most), its minutes count as movement in Life, and the kilometres feed a thirty-day line, a monthly club board and three badges (first run, ten runs, a hundred kilometres). A host can void an entry and the pay comes back out. Brand collabs have their own tab: staff with the events permission or a brand's own team post what the brand gives, what it asks and the giveaway; a host applies with the club; an accepted collab shows on the club page and on any run the host ties to it, so runners see the giveaway before they turn up. Every app's main screen ends with a "How it works" section of three to five concrete steps and the words it uses; Help holds every word we made up and the one list of how everything pays, and small nudges around the app point there. The ink is a near-black grey rather than brown, in both modes. Keys and routes keep their older names (`/tower`, `/realm`, `spark`) so nothing breaks. An animated pyramid (`components/Pyramid.tsx`, GSAP) teaches the layers: a tick lands on the tip and a glow runs down to the base. Onboarding shows it only after the answers, as a tappable pyramid with one card at a time under it: each layer, then why it is not a to-do list, then the one rule it will not work without, then what to expect; the Pillars page and every pillar page show it with the area's own words.

## Onboarding and the task gate

The vibe check first asks which relationships need work right now and only asks those floors, three taps each; the others wait on the Tower, which sends you to `/vibe-check?floor=<key>` for one floor at a time, and the answers merge. On the "derived from your answers" screen each floor offers a few value goals and projects to pick from, or a line to write your own, before it is built. The characters walk along the bottom of the screen as the questions progress (GSAP). The first three task ticks are free; after that a task needs ten minutes of age and a ten-minute gap since the last tick.

## Apps, sidebar and dark mode

Only school, work, army, journal, life and shop (plus profile and the core tabs) start on. The Apps page is a grouped list, each group in its relationship colour with its character: an app that is on opens on tap, an app that is off is grey and tapping it opens a sheet that asks before switching it on. Switching off happens only under You, Features, which carries the same group colours and the switches. Enabled apps appear in the laptop sidebar under collapsible category headings. Rank and Rewards are part of the game, not apps, and live under You. Every app screen opens with a back button. In dark mode each app's pages take a deep shade of its relationship's hue rather than plain brown (`data-accent` on the document, set by the module gate).

## Bond: friends and anonymous chats

Every person has a public page (`/u/<handle>` or `/people/<id>` from the community feed). What it shows is the owner's choice, set under Public page: one switch for the whole page, then links, portfolio, what they sell, their community posts, their activity (level, streak, pillars set up, badges; never journal or wellbeing), friend requests, and chats. The server enforces every switch, including on friend requests and chat openings; a switched-off page returns only the name. Bond lists friends, friend requests, and anonymous one-to-one chats: both sides keep an alias for good, whether the chat started from a friend, a person you met at an event, or someone at your circle table (opened by alias, so the id never reaches the browser). Circles have no reveal at all.

## Circles

Small anonymous groups near you, every week. Onboarding asks for interests and a city (and, optionally, a position that never leaves the server). Staff open a circle in a city, usually weekly: once the week's tables are set, the cron opens the next occurrence a week later at the same time, and cancelling the latest one ends the series. Joining asks one question, how you will show up: single (wear red), committed (wear white), or rather not say. Only the person sees their answer; the table reads it by colour. Each table's page carries a "How to show up" card with when, where, what to wear and the alias to ask for. People sign up; two days before, tables are set by a matcher that favours complementary interests (writer with video, on camera with behind camera) and keeps people within twenty kilometres. Everyone gets an alias and a character. The group chat opens twenty-four hours before the meeting and closes two days after; the table writes its own plan; anyone can reveal who they are once the chat is open, and revealed members can ask for introductions under Bond.

## Life dashboard

Five areas, physical, financial, emotional, mental and spiritual, each scored from what the person already logs (sleep, movement, mindful minutes, mood, journal, stress, tasks, sparks, finance, learning, the tower floors) with a week-on-week trend. Every part is a link to the screen where you act on it. Movement minutes are logged from the dashboard itself.

## The public site

`/` is the site: no account needed. The seven characters walk along the bottom of the page as you scroll and whichever relationship is on screen takes the lead. Each floor lists the features that serve it. `/explore` searches every listing (content rewards, opportunities, events, programs, tools, public campaigns) with a sign-in button that returns you to the thing you picked. `/features/:key` is a page per module with the pitch, how it goes, which floors it serves and the live listings for it. `/c/:code` verifies a course certificate; `/i/:token` shows an invoice to a client.

Listings come from the admin console (Admin, Listings: create, publish, feature) and from the modules themselves (a published opportunity, a verified tool, a brand making its campaign public).

## Content rewards and view tracking

A reward has a brand, a brief, a platform, a pool of points, a rate per thousand verified views, a cap per creator and a minimum view count. Creators submit a public link. YouTube numbers are read automatically when a key is set; everything else is typed by the creator and confirmed by a reviewer, with the full metric history kept. Payout is computed from confirmed views, never exceeds the pool, and is released by someone with the finance permission. Rejections can be disputed. A reward can be changed after launch by the staff who run it: every change bumps its version, is audited, and sends a note to everyone who already entered saying what changed.

## Bookings, done properly

Availability is written in the creator's own zone (set under Profile), with weekly ranges, days off and special hours per date, a buffer around each session, a minimum notice and a booking horizon per product. Slots are computed by one pure function in shared and shown to buyers in their own time. A slot is checked again at booking time, the unique index stops two people taking it, and buyers can move a booking to another open slot up to two hours before. Payout details (legal name, PAN, bank, IFSC, address) are submitted from Customers, reviewed in Admin, KYC; only the last digits are stored.

## Shop and growth

Product kinds: download, course (drip, quizzes, certificates), membership, session (availability, intake questions, race-safe slots), event (replays for sale afterwards), link, payment link (fixed or pay what you want), bundle, locked post and priority DM (a paid question answered within promised days). Free downloads can capture leads. Coupons, affiliates at twenty percent, a platform fee in basis points per creator, refunds, a customers list with CSV export and a payout breakdown.

Sales has filters and a CSV. Courses can be drafted from pasted notes: a Workers AI binding writes lessons and quizzes, otherwise a plain outline is parsed (`#` headings, `?` questions, `-` options, `*` the right one). Memberships can carry a period in months and renew by buying again. Tracked links come with a QR code.

Content: every post gets a tracked link at `/go/<code>`; clicks carry an id into checkout so the dashboard shows clicks, sales and revenue per post, with profile-direct sales shown honestly. Auto-DM: a keyword on a post sends a tracked link by private reply (queued for you when Meta is not connected; a simulator exercises the flow). Funnels chain posts, automations, links, leads, products and broadcasts with the count at each step. Sequences deliver a message to a buyer's inbox some days after purchase.

## Finance

Money in and out with a category, who it was with, and optional splits (someone else's share of a payment, marked paid later). Dues track what people owe you and what you owe them, settle in one tap, and can repeat monthly. Recurring entries post on a day of the month. Budgets per expense category, goals (save up, or earn by a date), and all-time totals next to the month. Points earned on the platform appear alongside.

## How the game works

A branching vibe check derives your ladders. Every day: check in, do the spark, tick a task. Tasks can carry a time and a length so Today shows the day's plan. Waits stop farming: ten minutes before a new task can be ticked, six rewarded ticks a day, server-checked dates, time-gated evolution. XP ripples up the ladder; points come from showing up and can be spent on rewards, products and tickets.

## Admin

`/admin` works with the admin key or an admin's session. People (search, role, permissions, Pro, honors, points, and a preview of exactly what one person sees), Flags (switch, minimum role, rollout, overrides), Listings, Orders (search by order, payment, buyer or page, the full timeline, a refund), Webhooks (what came in, replay), KYC queue, Ops (funnels from our own analytics table, the email outbox), Redemptions and the Audit log of every change. Sign-in, sign-up, anonymous sessions, lead forms and checkout are rate limited. People can export everything as one JSON file or delete their account from You, Account. `/sitemap.xml` lists the site, every feature page and every published creator page; policy pages live at `/terms`, `/privacy`, `/refunds`, `/contact` and `/pricing`.
