# Kreators Life

Seven relationships as a daily game, with a creator super app on top: public site, learn-and-earn modules, content rewards, a shop with attribution, finance, circles, a life dashboard.
Full spec and history: README.md, docs/DECISIONS.md, docs/build-map.html. Read the relevant section before changing anything.

## Stack
pnpm workspace. apps/web: React 19, Vite 7, Tailwind 4, PWA. apps/api: Hono on Cloudflare Workers with D1, plain SQL migrations in apps/api/migrations, cron every fifteen minutes. packages/shared: the domain model both sides import, with Vitest tests.

## Non-negotiable rules
- Money is integer cents or integer points. Use `money()` and `feeBps()` from shared. Never floats for money.
- Times are stored as UTC ISO strings. Zone conversion happens only through `zonedToUtc` and `slotsFor` in shared.
- Auth is hand-built on Hono and D1, no package: Bearer session tokens in `sessions` (two UUIDs), PBKDF2-SHA256 at 100,000 iterations (the Workers free-plan ceiling) with a 16-byte hex salt from `randomHex`, constant-time compare. `passwordProblem` in shared is the one password rule, used by the sign-up form, the change form and both endpoints. Sign-in answers the same for an unknown email and a wrong password, hashes against a decoy salt when the email is unknown so the timing matches, and is limited per address (10 a minute) and per email (20 per quarter hour, `limited` in ops.ts). `POST /me/password` needs the current password and deletes every other session. `secureHeaders()` runs on every API answer. Password reset: `POST /auth/forgot` answers the same for any email and mails a one-time link (32 random bytes, stored as a SHA-256 hash in `password_resets`, thirty minutes, one open per account); `POST /auth/reset` checks the rule, claims the token, sets the hash and deletes every session. Founder addresses in `apps/api/src/admins.ts` and `ADMIN_EMAILS` get the admin role on sign-up or sign-in (`promoteBootstrapAdmin`, audited); until mail verifies addresses, whoever signs up with one first gets it. Magic links were tried and removed (migrations 0018 and 0019).
- Every owner-scoped query filters by the session user id. Staff powers come from `can(user, permission)` in apps/api/src/db.ts.
- Payment code talks to apps/api/src/payments.ts, never to a provider SDK directly. A money order becomes `paid` only in the webhook after signature verification.
- Webhooks: verify the signature on the raw body, store the raw payload in `webhook_events`, then process. Duplicates are no-ops.
- The /go redirect writes the click after the redirect is sent and never stores a raw IP, only a salted hash.
- Journal and wellbeing data never reach brands, staff, the leaderboard or Club selection.
- Everything that pays out has a wait or a reviewer: task age, daily tick cap, verified views, finance permission for payouts.
- Only spacing values 8, 12, 16, 32, 64, 120 (tokens xs, sm, md, lg, xl, 2xl). Never hardcode hex colours in screens; use the theme tokens so dark mode works.
- Wording is universal and plain, readable by a teenager (Flesch 60 or above; `scratchpad/flesch.py` scores a file). The words are: seven *areas* (never tower or floor), each area is a *pyramid* with six *layers* (foundation, rule, feeling, proof, project, task; never pillar, principle, value goal, outcome, rung or ladder), the daily *small act* (never spark), the *Daily* tab (never Today as a screen name) and the *Profile* tab (never You; the public page module is *Public page*). App groups are Contribution, Creation, Connection, Reflection, Essentials, Operations and Internal (team only). Route paths and keys keep their old names. Every action in the app is a checkbox row with the `toy` hover affordance.
- Screens open with `PageHeader` (or `BackLink` on coloured headers) and are built from `Section`, `StatTile` and the charts in `components/Charts.tsx`. Every admin list is a `components/DataTable.tsx`: sort by any column, search, filter by a column's values, tick rows for bulk actions, and edit a cell in place (`edit` on the column says which call runs); the public site's "Go to app" goes to sign-in without a session and to Home with one, and "Start free" goes to sign-up. Numbers come before actions on any dashboard. No new shadow values; use `shadow-toy-soft` or the `toy` classes.
- Teaching: `components/Pyramid.tsx` is the one explainer for how an area works; onboarding shows it after the answers (results first, then what did it, then the one rule), and Areas and each area page show it too. Sheets have a close button and room to breathe (phone bottom padding is `pb-xl`). Daily, Areas and Profile are single full-width columns (`columns={false}`); dashboards may use two columns. Search is inline (`components/SearchBox.tsx`): results appear under the field as you type, never on a new page. The onboarding explainer shows one card at a time under a tappable pyramid, never a wall of sections.
- Animation: new motion is written with GSAP (`gsap` in apps/web); `motion/react` stays only where it already is. Respect reduced motion with `gsap.set`.
- Apps: only school, work, army, journal, life, shop (plus profile and the core tabs) are on by default; Rank and Rewards are not apps. The Apps page is a grouped list, each group in its relationship colour (`MODULE_GROUP_ACCENT`); an app that is off is grey and tapping it asks before switching on; switching off happens only under You, Features, where the same group colours appear. Enabled apps appear in the laptop sidebar under their category. Every app screen opens with `BackLink`.
- Layout: every screen is one full-width column on a laptop (`Screen` defaults to `columns={false}`); only Home flows into two. A new route starts at the top (`Root` in App.tsx; a hash still lands on its element). In a row of equal choices no button is solid until it is picked. `SearchBox` lights its border on focus, white (`onDark`) on a dark header.
- Interests come from `INTEREST_GROUPS` (grouped the way a dating app does, for everyone, not only creators), at most `MAX_INTERESTS` (10) on at once, always picked with `InterestPicker`.
- School content: the two real programs (Editing fundamentals, Skills using ChatCut and AI) are seeded by migration `0016_school_programs.sql`, generated from `scratchpad/school-seed.py`; their lessons are rewritten from the skill files in `apps/web/public/resources` and each lesson links the file it came from (`content_ref` under `/resources/`). Lesson bodies are the small markdown `components/Markdown.tsx` renders (`##`, `###`, `-`, `1.`, `>`, `**bold**`). The teaching voice: a hook, a promise ("In this lesson you'll learn"), short second-person sections, bold-lead bullets, a "Pro tip" and a "Result", then "The bottom line". Never seed placeholder programs; the smoke test's program is called "Smoke test program".
- Roles: `ROLE_META` gives each role a badge (`RoleBadge`) that sits on the profile picture and under the logo in the sidebar; earned badges never go on the picture or the sidebar. The Internal group (Observability at `/internal/observability`) exists only for staff and admins by `minRole`; the API behind `/api/internal` checks the role on every call, only an admin changes a role, never their own, and every change is audited. Journal and wellbeing never appear there. The build map is embedded there from `docs/build-map.html` (a `?raw` import), so there is one copy.
- Privacy on the public page: `PublicSettings` (one switch for the whole page, then social icons, links, portfolio, products, posts, activity, badges, friend requests, chats) is the owner's choice and the server enforces it in `pageFor`, `POST /bond/friends` and `POST /bond/chats`. Journal and wellbeing never appear on a page. A new part on the page gets its own switch.
- Links page: the public page is the door into the app, like a Linktree. Blocks live in `LinkBlock` (`users.links_json`, migration 0017): link (plain or featured), header, text, image, video (YouTube only, embedded from youtube-nocookie), carousel (up to `MAX_CAROUSEL_ITEMS` cards), at most `MAX_LINK_BLOCKS`; `parseLinkBlocks` in shared is the one validator (https only, bounded text) and runs on save and on read. Taps are page events with `ref = block:<id>`, counted for the owner only at `GET /me/link-clicks`. Edited with `components/LinksEditor.tsx` under Public page; rendered with `components/LinkBlocks.tsx`. Every public page ends with the "Made with Kreators Life" footer that links to the site home. Sidebar groups start folded; only the group of the app you are inside opens.
- Anonymity: circle members and Bond chats are aliases only, with no reveal; member ids never reach the browser (chats from a table are opened by alias).
- No demo or mock data, anywhere: there is no seed route, no demo flag on rows, no placeholder content. Sign-up creates the user and seven zero scores and nothing else. Test data lives only in the smoke server's own database on port 8788. Sign out is `components/SignOut.tsx`, in the laptop sidebar footer and the Profile tab; a device-only account is warned first and offered sign-up.
- Contrast rule, from the kit: on a solid colour fill (`bg-r1`…`bg-r7`, `bg-ink`, a `Hero`) every foreground element is white (`text-on-fill`, rings and lines in `var(--color-on-fill)` with an `rgba(255,255,255,0.3)` track, buttons `variant="light"`). Yellow is the one exception and takes `text-on-yellow`. Dark text and dark buttons sit only on cream, card and tint surfaces. Never put a brown ring, brown text or an ink button on a coloured card.
- Dashboards use the kit's chart vocabulary in `components/Charts.tsx`: `AreaLine` for trends, `PillBars` for days, `Gauge` and `Ring` for scores, `Donut` with `Legend` for shares, `Bubbles` for what comes up most, `CalendarGrid` for a month, `EmojiRow` for moods, `Sparkline`, `Segments`, `PillChain` and `WeekDots` on rows. Pick the chart that fits the data; a screen with numbers should never be a wall of text. Moods are `MoodFace`, not emoji. A hero or a coloured card carries one of the seven characters (`Avatar`) with a mood that follows its number. Every tracker screen shows a line over thirty days. Line charts (`AreaLine`, `MultiLine`) keep their frame on: y labels, baseline and gridlines show even with no data; only the small line inside a metric card turns `axes` off.
- Do not build the white-label app, a marketplace, instalments or native chat transport (see docs/DECISIONS.md).

## Commands
- pnpm dev (web on 5173, api on 8787)
- pnpm typecheck
- pnpm --filter @kreators/shared test
- pnpm build
- pnpm db:migrate:local
- bash <scratchpad>/blueprint.sh for the end-to-end smoke test. It runs against a second API on port 8788 whose database lives in the scratchpad (`wrangler dev --port 8788 --persist-to <scratchpad>/smoke-state --test-scheduled`, migrated with `wrangler d1 migrations apply kreators-life --local --persist-to <that dir>`), so the dev database on 8787 never fills with test accounts. Screenshots (`shoot.mjs`) use the same server unless SHOOT_ORIGIN says otherwise.

## Done means
Typecheck and build pass, shared tests pass, the smoke test passes, the spacing and colour scans are clean, and docs/DECISIONS.md has a line if the plan changed.
